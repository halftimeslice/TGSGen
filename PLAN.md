# TGSgen — Project Plan (v2, AI Generation)

> **Rewritten 2026-07-05.** This plan replaces the original rule-engine approach. The TGS design is now generated by AI (Claude API) using the TCAWS/AS standards as its rulebook. The previous plan's map tooling, sign library, and diagram output requirements carry over.

---

## Overview

A web-based Traffic Guidance Scheme (TGS) generator for NSW traffic engineers. The user selects the affected roads/footpaths on a satellite map and enters the closure details; **AI generates the complete TGS** — sign placement, tapers, distances, control method — compliant with the TCAWS manual and AS 1742.3. The result is drawn on the map, fully editable, and exportable as a formal PDF.

**End goal:** AI generation accurate enough that **no user editing is required**. Editing tools exist as the safety net while accuracy is tuned toward that goal — not as the destination.

## Standards & Scope

| Field | Detail |
|---|---|
| Jurisdiction | NSW (v1) |
| Standards | Transport for NSW TCAWS manual + AS 1742.3 (and related AS sign standards) |
| Users | Traffic engineers producing formal TGS designs |
| Speed zones | Up to **110 km/h** (full TCAWS distance tables) |
| Output | To-scale TGS on satellite map, editable, exportable as PDF |

### Job types in scope (v1)

- Lane closure with alternating traffic (stop/slow by day, portable signals overnight — multi-phase)
- Lane merge on multi-lane roads (taper only)
- Full road closure **with complete detour design** (AI selects the detour route and places detour signage on surrounding streets)
- Roundabouts (no separate mode — selected with the same start/end pin tool as roads; the app auto-detects a roundabout on the selected path and gives the AI its full layout so the AI designs the closures. Decided 2026-07-06, replaces the earlier clickable section-closure model)
- Works at intersections (side streets signed/controlled)
- Shoulder / verge works (no lane closed)
- Kerbside / parking lane closures
- Footpath closures and pedestrian diversion
- Bike lanes and shared paths
- **Mobile works** (line marking, mowing, sweeping — separate TGS style)
- Day/night multi-phase jobs

### Out of scope (v1)

- Motorways / freeway contraflows
- Rail level crossings
- Special events

## User Flow

1. User navigates to the worksite on the satellite map
2. User selects the affected roads/footpaths — snap to road, pick side/lanes. Roundabouts need no special steps: if the selected stretch passes through one, the app detects it automatically
3. App auto-fetches road data (classification, speed limit, lanes, geometry) from OSM with NSW defaults as fallback — user can override
4. User fills in the **closure details form** — work type, what's affected (road / footpath / both), duration, day/night, mobile or stationary, TGS number, engineer name
5. **AI generates the TGS** (see pipeline below)
6. The app **automatically checks** the AI's numbers against the TCAWS tables; failures are sent back to the AI to fix before the user ever sees them
7. The TGS renders on the map — **fully editable**: drag signs (distances update live), add signs from the catalogue, delete/swap anything, "reset to AI version" button
8. Export to PDF with title block, notes, legend, north arrow

## Architecture

**Frontend (React) + small helper server + Claude API**

| Component | Technology |
|---|---|
| Map & satellite view | Google Maps JavaScript API |
| Road/footpath selection | Existing map tooling (snap-to-road, lane side, roundabout auto-detect) |
| Road intelligence | OSM Overpass API + NSW default fallbacks |
| **TGS generation** | **Claude API (`claude-opus-4-8`)** via helper server. **Provider-swappable by design (decided 2026-07-06):** the AI call lives behind one interface in the helper server so switching to another provider (e.g. Gemini) is a one-file change. The automatic checker validates output regardless of provider; the test library scores providers objectively if we ever want to compare |
| Helper server | Minimal Node server — holds the API key, forwards generation requests (the key must never live in the browser) |
| Automatic checker | Deterministic validation of AI output against TCAWS tables, with auto-retry loop |
| Sign library | Existing SVG sign icons (SIGN_LIBRARY_CATALOG.md) |
| Diagram renderer + editor | Canvas/SVG overlay on the map, drag/add/delete interactions |
| PDF export | Canvas-to-PDF pipeline (jsPDF) |

## AI Generation Pipeline

### What the AI receives per request

1. **The rulebook** — TCAWS_RULESET.md + SIGN_LIBRARY_CATALOG.md (sent as reference with every request; cached to keep cost down)
2. **Closure details** — everything from the form
3. **Road data** — exact geometry, speed limit, lanes, road class for the selected roads
4. **One aerial/satellite snapshot** of the work area — for context (driveways, medians, intersections, pedestrian generators)
5. *(Later add-ons: Street View images, user site photos, example approved TGSs)*

### Ground rules baked into the AI's instructions

- **Images are for context and judgment only — never for measurements.** All distances come from road data and the TCAWS tables.
- Output must follow an exact structured format (JSON schema) the renderer can draw: sign codes with positions, taper geometry, buffer distances, control method, staffing, TTL timings, notes.

### Accuracy loop (core feature — serves the 100% goal)

1. AI returns a candidate TGS
2. App validates every checkable number against the TCAWS tables (taper vs speed, sign spacing, advance warning distances…)
3. Any failure → sent back to the AI with the specific errors → AI corrects → re-validate
4. Only a passing TGS is shown to the user

### Accuracy measurement

- Build a **test library of real approved TGSs**; re-run the generator against those jobs regularly and score the output
- Every manual edit the user makes is a signal — feed recurring corrections back into the AI's instructions

## Key Risks

| Risk | Mitigation |
|---|---|
| AI gets a number wrong | Automatic checker + auto-retry loop; editable output as safety net; test library scoring |
| AI output varies between runs | Structured output format + checker narrows variation; "reset to AI version" for edits |
| Rulebook gaps (new scope areas) | Second extraction pass before enabling each job type |
| API key exposure | Key lives only on the helper server, never in the browser |
| OSM missing tags / footpaths | NSW defaults + engineer override + aerial context |
| Detour design quality | AI must justify route choice; detour legs rendered for engineer review |
| Running cost | Prompt caching; expect cents per generation |
| Requires internet | Accepted trade-off of the AI approach |
